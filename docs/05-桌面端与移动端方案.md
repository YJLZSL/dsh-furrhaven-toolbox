# Furrhaven Studio · 桌面端与移动端方案（v2.0：DSH 官方框架魔改路线）

> 版本：2.0 | 2026-08-16 | 权威级别：规范（前端） | 上游来源：用户方向修正——「直接用 DSH 的框架，只不过魔改；因为就是按照 DeepSeek Harness 的基础做的，需要能够同步 DSH 官方框架」
> v1.0（独立 Tauri 栈）已作废并归档到 `prototypes/tauri-studio/`（仅保留主题与 Android 可行性记录）。

## 一、最终技术路线

| 层 | 选择 |
|----|------|
| 框架 | **DeepSeek Harness 官方框架 fork**（本仓 `dsh-framework/`，独立 git 仓库 `YJLZSL/dsh-furrhaven`，private） |
| 上游 | `upstream = https://github.com/deepseek-ai/deepseek-harness.git`；同步 = `scripts/sync-dsh.ps1`（fetch upstream → rebase furrhaven → preset 自测） |
| Furrhaven 层 | fork 内 `furrhaven/`：preset card-forge / plugin fh-tools / skill furrhaven-card / theme furrhaven-theme.css——**只加不改上游文件**，rebase 冲突最小 |
| 桌面形态 | 直接用 DSH 官方 Web/Desktop 壳（Cordis web UI），不另做 Electron/Tauri |
| 引擎关系 | `fh` CLI（furrhaven-core）继续作为 L1；DSH plugin 工具面薄封装 |

## 二、同步官方框架（用户硬性要求）

```powershell
.\scripts\sync-dsh.ps1 -SkipSslVerify   # 本机证书链不完整时加
```

流程：`git fetch upstream --prune` → `rebase upstream/master` → `node --test furrhaven/presets/card-forge/test/` → 显示 rebase 后 log/status。
规则：Furrhaven 改动只落在 `furrhaven/` 层；任何要改上游 `packages/` 的行为必须按 DSH repo AGENTS.md 走（package skeleton / tsconfig references / invariant / Agent Note / test gates），不允许直接塞裸文件。

## 四、前端美术与动画（沿用金箔暖纸工坊，目标移植进 DSH client）

- 色板：深褐木案 `#14100c/#1d1610`、米纸 `#f5eee0/#fdfaf3`、暖金 `#b8860b/#e8c87e`、墨褐 `#2b2118`、暖褐 `#8b7355`。
- 材质：纸张噪点 grain、顶部金线、火漆印章、衬线字体栈（Noto Serif SC / Source Han Serif SC / STSong）。
- 动画：面板 rise 460ms / 字节条 shimmer 2.8s / 浮尘 14s / 构建 spinner / 脏点脉冲；全部 `prefers-reduced-motion` 降级。
- DSH 接入要求：feature 组件只消费 `--dsw-*` 语义 token（docs/web-styling.md），不得出现字面颜色；主题包走 client plugin 注册三件套（tsconfig.client.json references + web-app cordis.patch.yml + package.json dependency）。

## 五、Android 可能性（结论记录）

- Tauri 路线实验（已归档）：Gradle 工程生成 ✅、arm64-v8a Rust .so 编译 ✅、APK 出包受本机 Gradle 证书/代理拦截未完成。
- **新路线建议**：DSH 官方为 Web-first 框架，Android 端优先复用 DSH Web UI 的移动端自适应 / PWA / WebView 容器，而不是维护第二套桌面壳；具体方案待 DSH 前端主题接入后立项。
