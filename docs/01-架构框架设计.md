## 一、定位与设计原则

**是什么**：一套「卡体写作 + 世界书 + 组件 + 正则 + 多平台导出」五合一的角色卡创作工具箱。参考项目（`个人角色卡（平台参考）\`）验证了方法论，工具箱把它**泛化为全类型**——兽人是第一等使用场景，不是边界。

**六条设计原则**：

1. **全类型，题材无关**：卡型（character/simulator/bigworld/…）与题材（兽人/现代/奇幻/…）正交。题材相关规则（玩家性别红线、专属词雷区等）做成**可选规则包**，项目级开关，不硬编码。
2. **单一事实源**：卡内容只在 IR 工作区编辑，平台产物（FD JSON/FC 资料包/FB md/V2V3 PNG）全是派生物；组件、正则、世界书同理各有单一源。
3. **知识内化为检查器**：平台硬知识（组件正则五坑、字节口径、上传怪癖、正则排序陷阱）全部 lint 规则化 + 口径数据表化。
4. **引擎与宿主分离**：核心是纯 Python 包（终端/CI 可跑）；DSH 是第一等宿主（preset+skill+plugin 薄封装）。
5. **门禁退出码文化**：`fh check` 退出码 0 = 可交付；AI 与人共用同一验收标准。
6. **危险操作防护优先**：审阅稿状态机锁、转换器置空校验、截断保护钩子——参考项目三次事故直接催生。

## 二、核心概念模型

### 2.1 卡型系统（Card Types）——第一等概念

卡型决定：IR 模板、组件集、系统条目集、回复格式骨架、规则包组合、构建目标。

| 卡型 | 说明 | 组件集 | 系统条目 | 参考 |
|------|------|--------|---------|------|
| `character` | 标准角色卡（AI 扮演单一角色，任意题材） | vn4 件套（vnHeader/vnMap/vnThought/vnFooter，可减配） | 5 件（角色/场景/目标/好感/关系） | 参考项目 17 卡 |
| `character.activity` | 活动卡变体（限定玩法/特殊 UI，如阿钢卡趣味 Footer） | vn4 + 活动覆盖件 | 同上 + 活动状态条目 | 参考项目活动卡 |
| `simulator` | 模拟器卡（AI 运行世界，玩家是主角自由行动） | sim3 件套（HUD/vnMap背包一体/Choices）+ phase 四态 | 世界时间/阶段/资源/事件线 | 参考项目僵尸百分百 |
| `bigworld` | **大世界卡**（开放世界：多 NPC+多区域+势力+事件时间线，单卡承载可自由探索的世界） | world4 件套（worldStatus/npcRoster/regionMap/eventLog） | 6 件（地点/在场NPC/世界时间/主线进度/玩家状态/已知情报） | **新设计**（§5.2） |
| `custom` | 用户自定义：模板 + 组件集引用 + 规则包组合 | 任意 | 任意 | 卡型生态（长期） |

**模板继承**：`character.activity` 继承 `character`；custom 可继承任意基型。卡型注册表 `fh.types` 开放注册（长期成为社区扩展点）。

### 2.2 规则包（Rule Packs）——题材与质量解耦

| 包 | 内容 | 默认 |
|----|------|------|
| `quality-core` | 好感节奏铁令 12/13（恋爱向可关）、性格内核铁律、活人感文风（破折号限额/死物比喻禁用/"不是A是B"≤2）、模板残留词扫描 | 开（可按卡型关闭子项） |
| `genre-furry` | 玩家性别红线、男男叙事约定、兽人专属词雷区表 | 项目级 opt-in |
| `genre-*` | 其他题材包（现代/奇幻/科幻…预留） | opt-in |
| `type-simulator` | 选项长度规则、phase 输出约束、不剧透红线 | simulator 卡型自动挂 |
| `type-bigworld` | NPC 一致性、世界状态追踪、势力立场连续性 | bigworld 卡型自动挂 |

规则 = lint 规则 ID + 参数（如专属词表、豁免表），全部项目可配置。**参考项目的 furry 规则进入 genre-furry 包，不再是全局默认。**

### 2.3 项目（Project）

一个工作区 = 多卡 + 共享资产：`shared/`（跨卡世界观条目库、角色总表）、`components/`（组件库）、`regex/`（正则规则库）、`rulepacks/`（本地规则包覆盖）。

## 四、三工坊详细设计（产品核心）

### 4.1 世界书工坊（fh.worldbook）

世界书是与卡体平级的**第一等创作面**（性价比最高的扩写位：独立 30k 额度）。

**条目模型**：一条 = 一个 md 文件（front-matter 元数据 + 正文 content）：

```markdown
---
id: 1785243199113        # 数字id（时间戳），构建器分配
keys: [灰狼, 钢蓝冷光, 狼耳]   # 数组；系统条目用「系统-」前缀
name: 卢卡斯·外貌特征
depth: 3                 # 短篇3/长篇4/系统0
priority: 500            # 系统1-5，内容500
constant: false          # 常驻开关
probability: 100
scope: card | shared     # 卡私有 or 共享库注入
---
正文内容……
```

**功能面**：

| 功能 | 说明 |
|------|------|
| 条目 CRUD + 分区视图 | 按 系统/内容/共享 分组管理；front-matter 编辑免手写 JSON |
| **keys 分析器** | 误触发检测：单字/泛词黑名单（你/车/伞/老板…）、跨卡专属词冲突（雷区表）、keys 覆盖度提示（正文关键概念未入 keys） |
| **触发模拟器** | 输入一段样例玩家消息 → 命中哪些条目（含递归扫描 depth=1 联动）→ 预览注入顺序与 token 占用 |
| 系统条目模板 | 按卡型实例化：character 5 件 / simulator 4 件 / bigworld 6 件（40-120 字动态指针格式） |
| 共享世界观库 | `shared/` 条目被多卡引用（蔚蓝市模式泛化）；引用关系图 + 改动影响面提示 |
| 预算计算器 | 常驻/触发分类统计；token_budget = 常驻×1.2~1.3 + 触发×0.5 封顶 30,000（口径表驱动） |
| 一致性 lint | 条目缺 id/keys/name、keys 非数组、引用失效（"详见§X"无对应）、NPC 喧宾夺主检测 |
| 导出目标 | FD world_info（含 Python-repr 兼容序列化）、FC 世界书、ST world info JSON、V3 character_book |

### 4.2 组件工坊（fh.components）

FD 式 VN 组件的**创作 + 管理 + 注入 + 验收**全链路。

**组件模型**：四件套单一源（html.html / style.css / script.js / meta.json），meta.json 声明**槽位协议**：

```json
{
  "name": "vnHeader",
  "label": "VN顶部场景面板",
  "slots": [
    {"name": "scene", "required": true, "desc": "场景名"},
    {"name": "atmosphere", "enum": ["晴","阴","雾","细雨","雨","暴雨","强对流","雪","夜"]}
  ],
  "theme": {"color-primary": "#D2B46A", "bg": "#07080A"},
  "render": "iframe"
}
```

**功能面**：

| 功能 | 说明 |
|------|------|
| 组件脚手架 | `fh comp new` 生成四件套模板（含槽位协议、主动报高样板、clean($) 检查样板）——新组件从合规起点开始 |
| **组件集管理** | vn4（角色卡）/ sim3（模拟器）/ world4（大世界）/ 自定义；每卡引用组件集 + per-card 主题参数（A5 主题色模式泛化：17 卡改色贴毛色 → 任意主题表） |
| 注入引擎 | extract（从现有卡/官方参考卡提取入库）/ build / inject --all\|--card / check（继承 components_lib.py 已验证架构） |
| **约束检查器**（平台五坑全规则化） | ①`$变量$` 只许出现在 html（script 从 DOM 读）；②id 必须字符串=name；③html 禁 style/script/meta/iframe 标签；④source ≤20,000（JSON 转义后）；⑤占位符 ↔ 消息标签参数名逐字对齐；+ 拉长四禁（infinite 真实动画/min-height/fixed 全屏/setInterval 改 DOM）+ css 花括号配对 + `node --check` + `:root` 禁用 |
| 演示页生成 | showcase 自动生成（每组件多状态展示：vnHeader 9 天气 × 主题色矩阵）；改库后重跑即同步 |
| 残留清理 | 构建时清理不在卡清单内的组件条目（残留组件 → 整卡导入失败的事故根治） |
| 槽位协议文档 | 由 meta.json 自动生成组件调用协议文档（AI 写回复格式时直接引用，不再靠手抄文档） |

### 4.3 正则工坊（fh.regex）

FC 式正则脚本（作用于 AI 回复的 find/replace 渲染规则）的创作与测试。

**规则模型**（YAML，人类可读可 diff）：

```yaml
- id: dialogue-bold
  name: 对话加粗
  find: '^>(.+)$'
  replace: '**$1**'
  flags: [MULTILINE]
  scope: ai_reply          # 作用域：ai_reply | user_input | world_info
  order: 10                # 执行顺序（小先大后）
  enabled: true
  notes: FC 统一渲染 v2.3 第1条
```

**功能面**：

| 功能 | 说明 |
|------|------|
| 规则库管理 | 项目级 `regex/` 库；规则包模板（内置 FC 统一渲染 v2.3 全 15 条，从参考项目迁移） |
| **测试台** | 输入样例 AI 回复 → 按序应用全部规则 → 渲染预览（Markdown/HTML 双视图）+ 每条规则命中高亮——正则改动的即时验收 |
| 排序陷阱检查 | 全匹配 wrapper 规则必须在最后（否则 `^`/`$` 锚到 HTML 边界）；单双星号互斥（`(?<!\*)\*(?!\*)` 模式库）；规则间覆盖冲突检测 |
| 引擎差异标注 | 规则标注目标引擎（FC 正则方言 / ST regex JSON / FD 已废弃正则→组件）；跨引擎导出时方言转换或告警 |
| 导出 | FC 正则脚本包（入上传资料包 05 目录）、ST regex JSON、V3 规范 regex 字段 |

## 五、特殊卡型设计

### 5.1 模拟器卡（simulator）——参考项目已验证，直接泛化

- **结构**：世界规则（personality 改写为"AI 运行世界的规则+叙事风格"）+ 资源/阶段体系 + 群像开场白（欺骗感铺垫→急转）+ 事件世界书。
- **组件**：sim3（HUD 信息+阶段驱动 / vnMap 地图背包一体 / Choices 选项）。
- **phase 四态**：假光明→灰暗→毁灭→解放；AI 输出 `<phase>` 驱动全组件色调同步（.ph-* 类四组件覆盖检查入 lint）。
- **红线**：不剧透（删系统提示性文案）；选项 20-40 字行动导向；每轮必出选项（灰暗期也不可省）。
- 泛化点：phase 体系参数化（四态只是默认配置，可自定义阶段机）。

### 5.2 大世界卡（bigworld）——新设计

**定义**：单卡承载一个可自由探索的开放世界——多 NPC、多区域、势力关系、事件时间线；玩家不是陪聊对象而是世界中的行动者。

**IR 扩展**（character 卡型字段之外）：

```
cards/{slug}/
├── card.yaml            # 卡型=bigworld；世界名/时代/基调/主题
├── world_bible.md       # 世界圣经：地理总览/历史/运行规则/叙事风格（替代单角色 personality）
├── npcs/                # NPC 名册：每 NPC 一 md（mini-profile：外貌/性格标签/归属势力/初始态度/口癖）
├── regions/             # 区域条目：每区域一 md（地点描述/可触发事件/邻接区域）
├── factions.yaml        # 势力表：立场/资源/相互关系矩阵
├── events/              # 事件库：条件触发条目（前置条件/keys/后果/一次性标记）
├── first_mes.md         # 群像开场白（世界切片式开场，非单角色迎宾）
├── response_format.md   # 大世界回复格式：面板协议+场景叙述+在场NPC对话（按名册口癖区分）+行动选项
└── worldbook/           # 系统条目 6 件 + 内容条目
```

**系统条目 6 件**（常驻，动态指针格式）：当前地点 / 在场 NPC / 世界时间（日+时段推进规则）/ 主线进度 / 玩家状态（位置/资源/声望）/ 已知情报。

**world4 组件集**（全部带槽位协议，继承幻景引擎视觉体系）：

| 组件 | 槽位（示例） | 功能 |
|------|-------------|------|
| worldStatus | date/time/weather/region/danger | 世界状态横幅（日期时段天气区域危险度） |
| npcRoster | npcs（名\|态度\|状态 多条）/focus | 在场 NPC 卡片列（态度色条：敌/冷/中/善/亲） |
| regionMap | loc1-7（name/sub/type 色）+ current | 区域拓扑图（ vnMap 七节点模式放大：区域级而非场景级） |
| eventLog | log1-3（时间线事件）/flags | 事件记录/线索面板（可折叠） |

**字节策略**（大世界最紧的约束）：卡体 50k 只放世界规则+叙事风格+面板协议；NPC/区域/事件全部压世界书（30k 独立额度）+ 共享库；NPC 名册超限时分级（核心 NPC 常驻 / 次要 NPC keys 触发 / 背景归区域条目一句话）。预算器对 bigworld 出**专项报表**（NPC/区域/事件/系统四类分别核算）。

**规则包 type-bigworld**：NPC 一致性（态度/口癖/立场漂移检测）、世界时间单调推进、事件一次性标记遵守、势力立场连续性。

### 5.3 卡型扩展机制

custom 卡型 = 继承基型 + 换组件集引用 + 换系统条目模板 + 组合规则包 + IR 扩展目录约定。全部声明在卡型模板 `fh.types` 注册（长期成为社区分享单元，见开发计划长期路线）。

## 六、L2 DSH 前端（DeepSeek-Harness 驱动层）

### 6.1 三扩展面分工（同 v1.0，工具面扩充）

| 扩展面 | 名称 | 职责 |
|--------|------|------|
| Agent preset | `card-forge` | persona（角色卡创作专家）+ 写卡域任务路由 + 首轮工具面 + 晋升机制（机制全盘对齐 router-standard） |
| Skill | `furrhaven-card` | 流程纪律路由（任务→必读→五步→自检），泛化 shouren-card |
| Plugin | `fh-tools` | 工具面：`fh_new/build/check/audit` + 工坊工具 `fh_wb_sim`（世界书触发模拟）/`fh_comp_check`（组件约束）/`fh_regex_test`（正则测试台）——后三个是 AI 创作时的即时反馈回路 |

### 6.2 card-forge 任务路由（写卡域分类表）

| 任务信号 | 模式 | 首轮核心工具 |
|---------|------|-------------|
| 新建卡/写开场白/写组件/写正则/批量生成 | **react** | read/write/edit + shell |
| 修卡/排查/审计/超限压缩/平台报错 | **spec**（先定位后动手，整体重写优先纪律） | read/edit/glob/grep |
| 模糊/混合 | **weak**（模型自路由，flash/pro 分型 persona 照抄 router-core） | shell + str_replace_editor |

**风神兼容四守则**（不变）：独立 preset 不改 router-standard 本体；service 行 isolate realm 不碰 host-plane；不注册 `dev_router_*` 冲突名（检测到 router-standard 在场时路由段让位）；持久会话事件推导阶段 + 零外部 import。

### 6.3 多模型分工（风神玩法产品化，不绑定实现）

| 环节 | 模型档 |
|------|--------|
| lint/审计/字节核算/跨卡扫描/正则测试 | flash |
| 初稿/脑暴/选项批量扩写/NPC 名册批量生成 | flash |
| personality/世界圣经整卡重写/开场白终稿/文风清洗 | v4-pro max |
| 模式隔离子任务 | `dev_mode_subagent`（react 子代理跑生成、spec 子代理跑审计） |

配置在 `fh.config.yaml`，skill 指引 AI 按表执行。

## 七、L3 项目工作区（fh init 产物）

```
<项目名>/
├── fh.config.yaml        # 目标平台开关/卡型启用/题材规则包(genre-furry…)/模型分工/雷区词表
```

## 八、关键机制（防事故层，全部继承自参考项目事故教训）

1. **构建指纹**：dist/ 每产物 = IR hash + 引擎版本 + 口径表版本；`fh check` 校验漂移。
2. **审阅稿状态机锁**：IDLE → export(加锁) → EDITING → apply(校验→回写→check→解锁)；EDITING 期间拒 build/export（根治 export 覆盖未回写事故）。
3. **截断保护钩子**：含组件标签的行永不截断；`<START>…<END>` 整组删；截断后自动跑配对 lint。
4. **模板置空校验**：deepcpy 模板构建后强制扫非本卡特征词，命中即失败（银辉事故根治）。
5. **整体重写优先**：spec 模式设定改版必须整分区替换 + 历史残留词验证（`fh check --rule=CONTENT-RESIDUE`）。
